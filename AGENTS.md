## What this project is

**AsciiCity** — a static browser minigame: walk around a real city (London,
and since wave 5 hilly central Kyiv) in first person, rendered as coloured
ASCII glyphs (retro terminal look) with a green "NAVIGATION" HUD. Vite +
TypeScript + three.js, no backend, deployed to GitHub Pages. The design contract is **`docs/architecture.md`** (module map,
exact exported signatures, shader, constants) and **`docs/data-format.md`**
(city.json schema, OSM → JSON rules). Tickets cite them by section — read the
cited section before writing code; if the ticket and the doc disagree, flag it
in your report instead of guessing.

## Layout

- `src/data/` — `types.ts` (PM-owned data model), `validate.ts`, `synthetic.ts`
  (deterministic test city), `load.ts`.
- `src/world/` — pure geometry builders (`buildings.ts`, `roads.ts`,
  `ground.ts`, `water.ts`, `terrain.ts`) on top of the PM-owned `mesh.ts`
  (`MeshBuilder`, `toGeometry`); `collision.ts`; `palette.ts`; `traffic.ts`;
  `sky.ts`; `textures.ts` (browser-only).
- `src/player/controls.ts` — pure `stepPlayer` + DOM `Controls`.
- `src/render/` — `scene.ts` (renderer/lights/fog/camera constants),
  `style.ts` (PM-owned `RenderStyle` contract + `STYLE_PRELUDE`), `post.ts`
  (`StyleRenderer`: target + quad + style switching), `styles/<name>.ts`
  (one look per module — ascii/gloom/solarized, braille, blocks, teletext,
  dither/gameboy, pico8, edges, hatch, matrix; `R` cycles, `?render=<id>`).
  A style is a fragment shader over the low-res scene target — read
  `style.ts` and architecture.md §4.11 before writing one.
- `src/hud/` — pure formatters, `ZoneIndex`, DOM `Hud`.
- `src/main.ts` — bootstrap and frame loop (architecture.md §5).
- `tests/` — vitest unit tests `tests/<module>.test.ts`; `tests/fixtures/`.
- `e2e/` — Playwright smoke test; screenshots in `e2e/__shots__/` (gitignored).
- `scripts/` — `test.sh` (unit-test entry used by run-tests.sh), `check.sh`
  (full gate), `fetch-osm.mjs` + `osm-convert.mjs` (OSM data pipeline).
- `public/data/city.json` (London) and `public/data/kyiv.json` (Kyiv) —
  GENERATED by `npm run fetch-data` / `fetch-data:kyiv`; never hand-edit,
  never `cat` them (megabytes) — inspect with `node -e` or `jq`.
  `scripts/dem.mjs` turns SRTM tiles into the `terrain` grid
  (`docs/data-format.md` §Terrain); tiles cache in `.cache/dem/`.
- `docs/` — the two PM-owned design docs plus the per-module notes tickets
  ask for.

## Conventions

- TypeScript `strict`, ESM, **named exports only** (no `export default`), no
  `any` — use `unknown` + narrowing. Node 22 APIs only (the worker image has
  node 22; the host has 24).
- Pure logic is separated from browser/WebGL wrappers: builders return
  `MeshData` (typed arrays) and never touch `document`/`window`; unit tests
  run in plain node. Anything that needs a canvas is browser-only and is
  covered by the e2e smoke + PM review — keep it thin and exactly per spec.
- three.js: `import * as THREE from 'three'` or named imports from `'three'`;
  nothing from `three/addons` unless the ticket says so.
- Tests: vitest `describe/it/expect`, one file per module, numbers via
  `toBeCloseTo`. Every ticket lists the cases its tests must cover — cover
  them all, by name, so the reviewer can find them.
- Dependencies: `package.json` / `package-lock.json` are **PM-owned after
  T-0001**. Need a package? Block with a `## Questions` entry — never
  `npm install <pkg>`.
- Docs: a one-line JSDoc on every exported function/class; each ticket names
  the `docs/*.md` file to write or update.
- Commits: `[T-NNNN] <title>`, only files inside the ticket's scope.

## Config

- Project config is root `tigerteam.toml` (optional `~/.tigerteam.toml` for
  machine-local facts).
- `test_cmd = "bash scripts/test.sh"` — the runner injects it as
  `TIGERTEAM_TEST_CMD`; `run-tests.sh` forwards your path arguments to
  `vitest run`.

## Commands

- Unit tests: `bash .tigerteam/scripts/run-tests.sh [tests/foo.test.ts]` —
  the ONLY way to run tests. The first run in a fresh worktree does `npm ci`
  (30–90 s), then vitest.
- Full gate: `bash scripts/check.sh` — install → `tsc --noEmit` → vitest →
  `vite build` → Playwright e2e (only if `e2e/` exists). Run it before
  finishing any ticket that touches build/config files or `src/main.ts`.
- Dev server: `npm run dev` (not needed for tests). Data: `npm run fetch-data`.

## Landmarks & gotchas

- A fresh worktree has no `node_modules`; `scripts/test.sh` installs from the
  lockfile automatically — do not `npm install` by hand.
- Coordinate system: `x` east, **`z` south**, `y` up; yaw `0` faces north
  (`−z`), `+π/2` east. Getting the `z` sign wrong mirrors the whole map —
  see architecture.md §3.
- Playwright is pinned to **1.55.1** because the worker image bakes
  chromium-1193 at `/opt/pw-browsers`; any other version tries to download a
  browser and fails offline.
- `src/data/types.ts`, `src/world/mesh.ts` and `src/render/style.ts` are
  PM-owned: import them, do not edit them.
- Terrain (wave 5): the world is flat unless `CityData.terrain` is present.
  Every builder takes a `HeightFn` (`(x, z) => y`, default `FLAT_HEIGHT` from
  `types.ts`) so London and the synthetic city keep rendering byte-identical
  geometry. The sampler and the heightfield share one triangulation
  (architecture.md §4.9) — never "improve" one without the other.
- Kyiv names are English (`name:en`) where OSM has them, else Ukrainian
  Cyrillic; the HUD `<pre>` renders both — do not transliterate.
- Visual-verification steps: if your model cannot view images, verify through
  `window.__asciicity` and the HUD text instead and say so in the report —
  the PM does the GPU visual review. Never fail a ticket over that.
