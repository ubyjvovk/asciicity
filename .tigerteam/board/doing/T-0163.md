## Goal
Turn the T-0162 prototype into the production converter that rebuilds
Tokyo's BUILDINGS from PLATEAU while keeping everything else from OSM.
The rules are LOCKED in docs/data-format.md "Tokyo from PLATEAU (wave 22)"
items 1–8 (PM wrote them from your spike's Q4/Q5 recommendations — read
them; the schema `Building.tiers` / `BuildingTier` is now in
`src/data/types.ts`). Your own `docs/plateau.md` is the research record.

## Context
- Entry point (npm script already added by the PM):
  `npm run fetch-data:tokyo-plateau` = `node scripts/plateau/tokyo.mjs --data public/data/tokyo`.
  It post-processes the EXISTING OSM-built tiled dataset in place: read
  `index.json` + all tiles, fetch/convert PLATEAU for every mesh covering
  the bbox (cache under `.cache/plateau/`), apply merge rules 1–5, and
  re-assign buildings to tiles with the SAME rule as
  `scripts/tile-city.mjs` ("buildings by unrounded vertex-mean centroid",
  `Math.floor(c / tileSize)`); roads/trees/woods/water untouched. Create
  new tiles if PLATEAU buildings fall in a tile that has none (and add it
  to `index.tiles`); keep `index.landmarks` resolving (names via rule 3).
- `tiers`: emit for stepped / complex LOD2 buildings from your
  `lod2Tiers` (≤ 64, each h ∈ [1, h], plan-disjoint); never with `roof`.
- ids: rule 1 (stable hash of `gml:id` in a range that cannot collide with
  OSM ids or curated extras −1000…−999999).
- Deterministic output (sorted input, stable ordering) so re-runs diff cleanly.
- Do NOT run it against `public/data/tokyo/` in this ticket (that is
  T-0166); run it on a COPY (`.cache/plateau/tokyo-copy/`) and report.
- Keep `fetch-cell.mjs` working (or fold it in) — tests stay green.
