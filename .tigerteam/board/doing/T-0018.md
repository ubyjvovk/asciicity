## Goal
The committed dataset does not pass `validateCity`: building `556686921` has
its first point repeated as its last point after 0.1 m rounding, and two
other rings contain consecutive duplicate points, so the app silently falls
back to the synthetic city (`buildings[2504].poly: first point must not repeat last`).
Make the converter emit only rings that pass the validator, add the
validator to the dataset test, and regenerate `public/data/city.json`.

## Context
- `scripts/osm-convert.mjs` (T-0003) builds rings in `toRing`; rounding to
  0.1 m happens there. After rounding: (1) drop any point equal to the
  previous point; (2) drop the last point while it equals the first;
  (3) drop the ring if fewer than 3 points remain or `|area| < 1`. Apply the
  same consecutive-duplicate removal to road polylines (drop roads left with
  < 2 points).
- `src/data/validate.ts` (`validateCity`) is now on `main` — import it in
  `tests/osm-convert.test.ts` and run it on the committed file. `.d.ts` only
  needs updating if you change exported signatures.
- Add to `tests/fixtures/overpass-small.json` one closed way whose second
  node is within 2 cm of the first and whose penultimate node is within 2 cm
  of the last (so both rules trigger after rounding) and one highway with two
  consecutive identical nodes.
- Regenerate with `node scripts/fetch-osm.mjs` (Overpass, 1–3 min; retry logic
  exists). Building/road/place counts must stay within ±5 % of the previous
  run (`3118 buildings, 10307 roads, 43 places`). If Overpass is unreachable
  after retries, block with `## Questions`.
- Add a "Ring cleaning" note to `docs/fetch-osm.md`.
