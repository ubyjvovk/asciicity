## Goal
User review of the `lowpoly` style: (1) "3–4 weird horizontal lines in the
middle, present most of the time" — a depth-sampling seam bug; (2) "make it
upbeat and shiny, characteristic of early 3D renders". Both are locked in
`docs/architecture.md` §4.11, paragraph "`lowpoly` v2 (T-0129 …)" — read it
first; it is the contract. Everything else about the style stays as is.

## Context
- Bug: in `LOWPOLY_FRAGMENT` the depth samples use `centreUv = (cell +
  0.5) / grid` and `stepUv = 1.0 / grid`. With sub 2×2 that centre sits on
  the seam between two depth texels. Replace with texel-centre sampling
  exactly as §4.11 says: `texel = 1.0 / sceneSize; centreUv = (cell * sub
  + 0.5) * texel;` neighbours at `± sub * texel`. Keep the edge rule and
  `isLowpolyEdge` untouched otherwise.
- Shine: update `LOWPOLY_LUM`, add `LOWPOLY_SHINE = 0.75`, `LOWPOLY_GREY`,
  `LOWPOLY_PASTEL = 0.12`, new `LOWPOLY_SKY` values; `lowpolyColour`
  implements the full v2 path (pastel hue or chrome grey × band, then the
  shine mix when `v ≥ 0.92`). The shader mirrors it term for term.
- `tests/styles/lowpoly.test.ts`: update the cases whose expected values
  change (`lowpolyColour([1, 1, 1], 0.45)` is now a shine colour;
  `[1, 0.1, 0.1]` → pastel red × 1.0 then shine; `LOWPOLY_LUM`/`LOWPOLY_SKY`
  constants) and ADD, by name:
  1. `lowpolyColour([0.5, 0.5, 0.5], 0.45)` → grey branch: equals
     `LOWPOLY_GREY · LOWPOLY_LUM[posterLevel(0.5^0.45)]` (toBeCloseTo);
  2. `lowpolyColour([1, 0.1, 0.1], 0.45)` → each channel equals
     `mix(mix(HUES[0], 1, 0.12) · 1.0, 1, 0.75)`;
  3. `lowpolyColour([0.8, 0.08, 0.08], 0.45)` (v ≈ 0.905 < 0.92) → NO shine:
     equals `mix(HUES[0], 1, 0.12) · LOWPOLY_LUM[3]`.
- `e2e/lowpoly.spec.ts`: rebuild the expected set from the pure exports as
  §4.11 says (call `lowpolyColour` on representative inputs per hue/band
  plus the shine inputs, or export a `lowpolyPaletteSet()` helper from the
  style module and use it). Keep assertions 1–6 and their thresholds; ADD
  by name:
  7. no seam lines: in the default un-aimed noon frame, every pixel row
     with `y > 0.55 · height` has < 80 % of its pixels within 12/255 of
     `LOWPOLY_INK`/black (count rows that violate; expect 0). Quote the
     worst row's ink fraction in the report.
- `docs/styles/lowpoly.md`: update the algorithm (texel-centre depth,
  pastel/chrome/shine, new constants) and the constants table.
- If your model cannot view images say so; the PM does the GPU review.
