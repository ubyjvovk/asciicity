## Goal
The `LANDMARKS ▸` row (stub from T-0060) opens a scrollable list of the
current city's presets (`presetsFor(city)` from T-0059, table order,
labels); choosing one teleports the player there exactly as `?at=` would,
per `docs/architecture.md` §4.13 "Fast travel".

## Context
- Submenu: replace the menu rows with a list of `button.landmark` (label
  text) plus a `◂ BACK` button; `Escape`/`BACK` returns to the main menu.
  Style like the existing `.menu-btn` rows; the list scrolls inside
  `#menu` (`max-height: 60vh; overflow-y: auto`), stacked full-width on the
  ≤ 700 px breakpoint.
- Teleport: `const sp = resolveSpawn(key, city.origin, blocked, city, cityInfo.defaultSpawn)`
  → `state.x = sp.x; state.z = sp.z; state.yaw = sp.yaw; state.pitch = 0; state.fly = false; state.y = groundAt(sp.x, sp.z) + EYE_HEIGHT`;
  toast `→ <LABEL>`; `history.replaceState` with `at=<key>`; hide the
  overlay and re-request pointer lock on non-touch. Expose
  `window.__asciicity.travel(key: string): boolean` (same code path; false
  for unknown keys) so the e2e can drive it.
- e2e: `smoke: fast travel` on `/?city=kyiv` (real data is fine here, it is
  served statically): call `__asciicity.travel('lavra')`, assert the state
  moved > 1 km from Maidan and the HUD `ZONE` row changed; open the gear
  menu, click `LANDMARKS ▸`, assert ≥ 15 `button.landmark`, click the one
  whose text contains `Golden Gate`, assert `__asciicity.state` is within
  250 m of the Golden Gate centroid (compute from `public/data/kyiv.json`
  in node) and the URL contains `at=goldengate`.
- Docs: `docs/integration.md` (fast travel section, `__asciicity.travel`).

### Notes for the reviewer
- `travel` short-circuits `state.y` via `groundAt(sp.x, sp.z) + EYE_HEIGHT` per the ticket, so the eye sits on whichever surface the resolver picked (bridge decks and terrain both flow through `groundAt`). If the player was flying, `travel` also snaps the camera far plane back to 2000 to match `state.fly = false`.
- The desktop e2e follows the panels-test pointer-lock dance (release lock → hide overlay → click gear) because `travel()` re-requests lock on desktop. `page.evaluate` doesn't count as a user gesture, so in headless the lock request usually fails silently, but the release path is still safe.
