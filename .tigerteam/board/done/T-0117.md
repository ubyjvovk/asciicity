## Goal

Add a second bare-earth filter mode, `ridge`, that removes roof
contamination without shaving real bluff crests: T-0115 measured the
wave-13 9×9 erode cutting 19 m off the Lavra crest and 12 m off the
funicular bluff (real relief) while still under-flattening streets. The
`ridge` mode is a directional opening — roofs have low ground in every
direction, crests keep a high ray along their plateau.

## Context

- **The contract is `docs/data-format.md` step 3b, "`ridge` mode"** —
  the exact algorithm (8 half-rays × 4 nodes including the centre,
  `H1 = max over rays of ray-min`, then the existing double 3×3 smooth),
  its properties, and the CLI shape. Read it first.
- T-0115's blocked report (`.tigerteam/board/blocked/T-0115.md` — or
  `todo/` once answered) carries the Kyiv measurements motivating this.
- Implementation home: `scripts/dem.mjs` beside `erode`/`smooth` — a new
  pure `ridgeOpen(heights, cols, rows)` (same array→array signature,
  reads only the input grid). `Dem`'s `bareEarth` option and
  `buildTerrain` currently treat it as boolean; make the option
  `false | true | 'ridge'` (`true` = the wave-13 erode path, byte-for-
  byte unchanged), and pick the first pass accordingly. Update
  `scripts/dem.d.ts` (established pattern).
- CLI: `scripts/fetch-osm.mjs` currently forwards `--dem-bare` as a
  boolean. Accept `--dem-bare ridge` (the T-0100 parser already
  consumes a value token); `--dem-bare`/`--dem-bare 1`/`true` keep
  meaning the erode mode. Any other value throws loudly.
- Do NOT touch any committed dataset — this ticket is code + tests only.
  Kyiv's regen re-runs afterwards as T-0115 (already answered to depend
  on this ticket).

**Notes for the reviewer:**
- The pickup of the first pass by mode: `buildTerrain`'s `useBare` is now
  `bare ?? (dem && dem.bareEarth ? dem.bareEarth : false)` instead of the old

  green).

  blob that IS cut to 0. If the PM intended a flush corner to be cut, that
  reading conflicts with the step-3b algorithm as written.
