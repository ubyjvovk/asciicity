## PM answer (2026-09-19) — option 1, plus one more rule

**1. Walk timeout.** `e2e/minastirith.spec.ts` is added to your scope for
exactly this: raise the walk `waitForFunction` timeout at line ~137 from
`90_000` to `170_000` and the describe timeout on line 12 from `180_000`
to `300_000`. Nothing else in that spec changes. The assertion is "the
ramp exists"; crayon under SwiftShader is simply slower now.

**2. Sky patches — new rule 1' in §4.11 v3** (user: "the sky does NOT
have to be completely blank everywhere"), on `main`
(`git show main:docs/architecture.md | grep -n "1'. SKY"`). Verbatim:

    n1s   = vnoiseA(ps.x, ps.y, 1, 1, 30, 12)                        // big patches, 30 cells
    n2s   = vnoiseA(ps.x, ps.y / 6, 1, 1 / 6, 6, 13)                  // sideways smear
    horiz = 1 − smoothstep(0.05, 0.45, clamp(s.dirW.y, 0, 1))        // 1 at the horizon, 0 high up
    skyShade = 0.22 · smoothstep(0.58, 0.85, n1s) · (0.55 + 0.45 · n2s) · (0.35 + 0.65 · horiz) · g
    out = mix(PAPER_P, skyCol, skyShade)     // skyCol = G (pencil) | SKY_PENCIL = (0.40, 0.46, 0.62) (crayon)

`skyCol` is a colour-side variable like `groundCol`; the sky shade lives
inside the RULES block. New pure `skyShadeOf(n1s, n2s, horiz, g)` with a
unit case: `skyShadeOf(0.5, ·, ·, 1)` → 0; `skyShadeOf(1, 1, 1, 1)` →
0.22; `skyShadeOf(1, 1, 0, 1)` → 0.077 (toBeCloseTo 3). Docs: rule 1 in
both style docs.

Then the acceptance commands and `bash scripts/check.sh` end to end,
commit, hand off. Do not open any `.png`.
