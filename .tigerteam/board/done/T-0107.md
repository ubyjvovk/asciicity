## Goal
SRTM is a radar surface model: in Tokyo, roofs contaminate street
elevation (the flat Shibuya Scramble reads 36–45 m ASL and ±10 m lumpy;
reality is a flat ~16 m valley floor). Implement the locked bare-earth
filter behind a new `--dem-bare` boolean flag. Filter code only — the
Tokyo refetch is T-0108.

## Context
- **Read first**: data-format.md "Terrain" step **3b** — the complete
  locked algorithm (erode = second-smallest of the 5×5 window; smooth =
  mean of the 3×3 window; applied to the ABSOLUTE grid between steps 3
  and 4; datum recomputed from the filtered grid; water levels derive
  from the filtered grid; grid dims/step/0.1 m rounding unchanged).
- Implement the two passes as exported pure functions in
  `scripts/dem.mjs` — `(heights, cols, rows) → heights` (new arrays, no
  input mutation; each output node reads only the input grid). Update
  `scripts/dem.d.ts` (existing pattern).
- `scripts/fetch-osm.mjs`: add `'dem-bare'` to `BOOLEAN_FLAGS`; enable
  the filter when `dem-bare` is `true | '1' | 'true'` (mirror `tiles`).
  Update `scripts/fetch-osm.d.ts` if any typed surface changes.
- Windows clip at grid borders (use the values available; erode with < 2
  values in the window = the minimum).
- Verify against the CACHED real tile if `.cache/dem/N35E139.hgt.gz`
  exists — do not re-download for tests; unit tests use synthetic grids
  only, no network.

### For the reviewer
- Design decision: the `--dem-bare` flag is plumbed via a `bareEarth`
  property on the `Dem` instance (set by `fetchDemTiles`), because
  `scripts/osm-convert.mjs` is explicitly out of scope. `buildTerrain`
  reads `bare ?? dem.bareEarth ?? false`, so the flag can also be set
  directly on the opt (used by the unit tests).
- The bare-earth path samples water levels by BILINEAR interpolation of
  the filtered grid at ring vertices (the ring vertices are continuous
  local (x, z), not necessarily grid nodes). This matches data-format.md
  3b's "Water levels (step 4) are computed AFTER filtering, from the
  filtered grid".
- The regression test proves the default path is byte-identical to the
  unchanged behaviour; the Tokyo cached tile is not present under
  `.cache/dem/N35E139.hgt.gz`, so no real-tile check was possible (ticket
  said "if it exists" — deliberately opt-in).
- Out-of-scope observation (not touched): `docs/fetch-osm.md` still lists
  the Central Tokyo command without `--dem-bare`. T-0108 is the refetch
  ticket; it should update that command line to include `--dem-bare` and
  the summary snapshot when Tokyo is refetched.
