## Goal
Make islands walkable: `CollisionGrid` takes the water rings as its own
argument and treats a point as water only when it lies inside an ODD number
of rings (Alcatraz's island ring inside the Bay ring = land). Contract:
`docs/architecture.md` §4.6 (wave-9 paragraph) — read it first; it is the
spec. Mirrors data-format.md "Coastline water" rule 6 (terrain flattening
already uses parity).

## Context
- Today `src/main.ts` (≈ line 446) merges `city.water` rings into the
  building list as fake footprints (`id: -1 - i, h: 1`) → "inside any ring
  = blocked". Replace with `new CollisionGrid(city.buildings, 25,
  corridors, city.water ?? [])` — keep the existing corridor argument and
  everything else in main.ts untouched (main.ts is shared; touch only that
  construction site).
- `src/world/collision.ts`: new constructor signature `constructor(buildings:
  Building[], cell = 25, corridors: Corridor[] = [], water: Vec2[][] = [])`
  — default keeps every existing caller/test valid. Bucket ring EDGES per
  grid cell like footprint edges (for the `r` shore margin) and keep each
  ring with its bbox for the parity test.
- `blocked(p, r)`: unchanged footprint test, then water: count rings whose
  bbox contains `p` and for which `pointInPolygon(p, ring)` is true — odd
  ⇒ blocked; additionally blocked when within `r` of any bucketed ring edge
  (both sides of every shore). Corridors override footprints and water
  alike (existing rule; keep the order of checks so corridors still win).
- Performance: `blocked` runs several times per frame; the Bay ring has
  ~1000 vertices. Parity test only over rings whose bbox contains `p`
  (44 bbox checks, then ≤ 2 ray casts in practice). No allocation.
- `tests/collision.test.ts` — keep every existing case green byte-for-byte
  (London/Kyiv have no nested rings so their behaviour is identical), add:
  - `'a point inside one water ring is blocked'` (single square ring)
  - `'a point inside an island ring nested in a water ring is walkable (odd parity)'`
  - `'a point within r of an island shore is blocked from both sides'`
  - `'a bridge corridor over water stays walkable with parity water'`
  - `'Alcatraz: the lighthouse centroid is land and a point 300 m south of it is water'`
    — load `public/data/sf.json` (pattern: `tests/landmarks.test.ts`),
    build `new CollisionGrid([], 25, [], city.water)` (no buildings), use
    the centroid of the building named `Alcatraz Island Lighthouse` and the
    point `[cx, cz + 300]`.

### Design notes
- `waterRings` is a plain array iterated linearly (44 rings in SF, 0 in
  London/Kyiv, cheap enough with the bbox short-circuit — matches the
  ticket's performance target of "44 bbox checks, then ≤ 2 ray casts"). No
  bucketing for rings themselves because a huge Bay ring covers most cells
  anyway; edges are bucketed for the shore margin as the ticket requires.
- Shore-margin loop uses a `seen: Set<WaterEdge>` mirroring the footprint
  loop (edges bucket into up to 3 cells; 3×3 iteration would double-count
  otherwise).
- Parity used `inside & 1` — no allocation, integer bitwise ⇒ same result as
  `inside % 2`.
