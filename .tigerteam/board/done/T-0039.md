## Goal
A pure, zero-dependency node module that turns public SRTM 1-arc-second
tiles into the `terrain` grid (+ `waterLevels`) described in
`docs/data-format.md` §Terrain. Wave 5 makes central Kyiv hilly; this is the
data half. T-0040 wires it into `fetch-osm.mjs` — this ticket does NOT touch
the fetch script or the converter.

## Context
- Read `docs/data-format.md` §Terrain (tile naming, HGT layout, bilinear +
  void rule, grid formula, water flattening) and `src/data/types.ts`
  (`TerrainData`). Those are the contract; if anything here contradicts
  them, flag it in your report.
- Projection helpers already exist in `scripts/osm-convert.mjs` (`project`,
  `round1`); import them — do not re-implement. You need the inverse too:
  add `unproject(x, z, origin)` **in dem.mjs** (the formulas are in
  `docs/data-format.md` §Coordinate system: `lon = origin.lon + x / (cos(origin.lat°)·111320)`,
  `lat = origin.lat − z / 110574`).
- Point-in-polygon: copy the ray-casting loop from `src/world/collision.ts`
  into dem.mjs (scripts cannot import TS).
- Exports (JS + matching `scripts/dem.d.ts` in the style of
  `scripts/osm-convert.d.ts`):
  ```js
  export function hgtTileName(lat, lon)                    // 'N50E030' (floor of lat/lon; S/W for negatives)
  export function hgtUrl(name)                             // https://s3.amazonaws.com/elevation-tiles-prod/skadi/N50/N50E030.hgt.gz
  export function decodeHgt(gunzippedBuffer)               // { side, samples: Int16Array }  (side = sqrt(bytes/2), must be an integer ≥ 2)
  export class Dem {                                       // constructor(tiles: Map<tileName, {side, samples}>)
    elevationAt(lat, lon)                                  // bilinear, void-aware; throws Error naming the missing tile
    get voids()                                            // number of void corners substituted so far
  }
  export async function fetchDemTiles(bbox, { cacheDir = '.cache/dem', fetchImpl = fetch } = {})  // → Dem; every tile touching the bbox; cache <cacheDir>/<name>.hgt.gz; gunzip via node:zlib
  export function buildTerrain({ bbox, origin, dem, step = 20, waterRings = [] })  // → { terrain, waterLevels }
  export function unproject(x, z, origin)
  ```
  `buildTerrain` follows data-format.md steps 1–4 literally (`waterRings`
  are the already clipped local-metre rings the converter produces;
  `waterLevels[i]` per ring, nodes inside ring `i` set to that level).
- `docs/fetch-osm.md`: add a `## Terrain (scripts/dem.mjs)` section: the
  tile source, cache dir, the formulas by reference to data-format.md, and
  how to run the tests.
