## Goal
The user: "not enough neon signs — can we get a bunch of cyberpunk-style
neon signs (maybe best to start with Tokyo)". Today the rule places one
small sign on ~12 % of street-facing walls. Make Tokyo's streets DENSE with
neon — Shinjuku/Shibuya style: several signs stacked up each facade,
vertical blade signs, stacked small panels, big facade screens, two-colour
tubes, coloured glow on the walls — and double the density elsewhere. The
design is LOCKED in docs/architecture.md §4.11 "Neon v2 — dense city
profiles (wave 23b, T-0168)" — read it first, plus "Neon signs" (v1) and
the §4.2 "Tiers" paragraph (use `exteriorWalls`, as T-0165 already does).

### For the reviewer
- **Screen share tuning:** only about ⅓ of Tokyo's signs are on buildings ≥ 30 m, and screens are only allowed there. A flat 8 % roll gave about 2 % screens overall, so on eligible buildings the screen roll is 35 % (`SCREEN_TALL`), and screens take the building's longest active wall. That brings the whole city to about 8 %. This is documented in the code and the doc.
- **Stack panels (spec ambiguity):** the spec says stacks "rotate their glyph column into a portrait slot", but it also gives stack panels as 1.6 × 0.9 m (w × h, which is landscape, like every other size in that section). I kept the landscape panels and put the word on one line in a landscape slot. Only blades are rotated. It's a one-line change in `neonSlotRotated` if the PM wants portrait stacks.
- **Atlas saturation:** the atlas fills all 128 slots in Shinjuku almost at once. With `kind|word|text|border` keys there are about 4 × 50 × 56 combinations, so most later signs reuse `hash % 128` slots, as the spec asks. As a result, a reused slot's colours can differ from the sign's glow card and spill-light colour. If this reads badly on the GPU, one option is to derive the colour pair from the word.
- **`neon.buildMs` of 90–100 ms per cell** on the swiftshader container, which competes with the CPU rasteriser. In node, the whole tile (placement plus meshes) takes about 90 ms, so real hardware should be much lower. Still worth checking on the MacBook for hitching.
- **Structure:** `buildNeonMeshes` and the slot table live in `neonplace.ts` (the pure sibling) so the budget tests measure the real geometry. `neon.ts` is now a thin wrapper.
- **Flicker seed:** it now mixes in `y`, so signs stacked up one facade don't flicker together. London flicker is 6.6 %, inside the 4–12 % band.
