## Goal
Fix a movement annoyance in `Controls`: holding `W` then pressing `S` and
releasing `W` currently zeroes `forward` even though `S` is still held. Track
the set of held key codes and recompute every axis from it on each key event.

## Context
- `src/player/controls.ts` (T-0008) — `Controls.onKeyDown/onKeyUp` set axes
  directly. Keep the public API (`readInput`, `dispose`, key map in
  `docs/controls.md` and architecture.md §4.7) unchanged; `stepPlayer` is
  untouched.
- Implementation: a private `held: Set<string>` of `KeyboardEvent.code`;
  `keydown` (non-repeat) adds, `keyup` deletes, then a private
  `recompute()` derives `forward = (W|Up ? 1 : 0) + (S|Down ? -1 : 0)`,
  `strafe = (D ? 1 : 0) + (A ? -1 : 0)`, `turn = (Right ? 1 : 0) + (Left ? -1 : 0)`,
  `sprint = ShiftLeft|ShiftRight held`. Opposite keys held together cancel
  to 0. Also clear `held` and recompute on `window` `blur` (keys released
  while the tab is unfocused would otherwise stick).
- To make this unit-testable in node, export a pure helper
  `axesFromHeld(held: ReadonlySet<string>): Pick<InputState, 'forward' | 'strafe' | 'turn' | 'sprint'>`
  and have `recompute()` call it.
