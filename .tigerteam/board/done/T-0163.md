Turn the T-0162 prototype into the production converter that rebuilds
Tokyo's BUILDINGS from PLATEAU while keeping everything else from OSM.

## Context
- Entry point (npm script already added by the PM):
  `npm run fetch-data:tokyo-plateau` = `node scripts/plateau/tokyo.mjs --data public/data/tokyo`.
  It post-processes the EXISTING OSM-built tiled dataset in place: read
  `index.json` + all tiles, fetch/convert PLATEAU for every mesh covering
  the bbox (cache under `.cache/plateau/`), apply merge rules 1–5, and
  re-assign buildings to tiles with the SAME rule as
  `scripts/tile-city.mjs` ("buildings by unrounded vertex-mean centroid",
  `Math.floor(c / tileSize)`); roads/trees/woods/water untouched. Create
  new tiles if PLATEAU buildings fall in a tile that has none (and add it
  to `index.tiles`); keep `index.landmarks` resolving (names via rule 3).
- `tiers`: emit for stepped / complex LOD2 buildings from your
  `lod2Tiers` (≤ 64, each h ∈ [1, h], plan-disjoint); never with `roof`.
- ids: rule 1 (stable hash of `gml:id` in a range that cannot collide with
  OSM ids or curated extras −1000…−999999).
- Deterministic output (sorted input, stable ordering) so re-runs diff cleanly.
- Do NOT run it against `public/data/tokyo/` in this ticket (that is
  T-0166); run it on a COPY (`.cache/plateau/tokyo-copy/`) and report.
- Keep `fetch-cell.mjs` working (or fold it in) — tests stay green.

### Reviewer notes
1. **Detecting OSM parts is a heuristic.** Our tiles no longer carry the `building:part` tag, so rule 5 needs another test.
   - A "stack" is a set of OSM buildings whose footprints overlap by ≥ 50 % of the smaller one. Every member of a stack that holds a raised part (`minH > 0`) or ≥ 3 distinct heights counts as a part.
   - On the real data that flags 439 buildings: Skytree's decks and mast, Tokyo Tower's 30 concentric grounded tiers, but also some multi-height OSM mappings such as LaQua and Harumi Flag.
   - The plain "any overlap" version flagged 944, including duplicated outlines like the Bank of Japan's.
   - Rule 5 coverage uses the union of the parts, so stacked parts count once.
2. **Rule 3 loses some names.** 455 of 14 496 distinct OSM names (3 %) don't transfer, `Shibuya` among them: PLATEAU splits the station complex into buildings that neither match it at IoU ≥ 0.5 nor cover it ≥ 50 %. 682 new names come in from PLATEAU `gml:name`. A fallback would recover them ("a named OSM building whose name went nowhere → the PLATEAU building overlapping it most"). That changes a locked PM rule, so I did not implement it.
3. **Tiers are split into disjoint pieces.** `unionFacets` dropped holes, which makes a podium tier overlap its tower (not plan-disjoint). `splitHoles` cuts holed rings open instead: 23 540 buildings keep their tiers, against 18 311 without it (6 837 rejected), for +5 MB. Remaining rejects (1 724 overlaps from overhanging facets or T-junction unions) fall back to the envelope.
4. **Which buildings count.** PLATEAU buildings enter by vertex-mean anchor inside `index.bbox`. PLATEAU buildings get no `osmColor`/`material`/OSM roofs (the Tokyo tiles have none today anyway).
5. **Re-running.** The CLI refuses a dataset that already holds PLATEAU ids. T-0166 must run it on a fresh OSM dataset, and can pass `--cache` to reuse this worktree's 8.4 GB cache: `/home/d/asciicity/.tigerteam/worktrees/T-0163/.cache/plateau`.
6. **Not verified.** I did no visual check (no image viewing); the PM GPU review should use `.cache/plateau/tokyo-copy`.
