## Context
- `ctx.traffic()` returns the CarFleet InstancedMesh (`src/world/traffic.ts`):
  instance matrices updated every frame; boxes centred at ground +
  `CAR_HALF_HEIGHT`, rotation.y = −heading. Import the constants from
  traffic.ts (read-only).
- Models come in WILDLY different units and orientations (measured by the
  PM): bbox sizes range 0.02 m to 199 m; most have their length along z,
  the Town Car along x (manifest `yaw` = π/2). Normalise per manifest:
  apply `yaw`, scale so the bbox extent along z = `length`, origin at the
  bbox bottom-centre. The FORWARD direction (+z vs −z) is not verified —
  the PM will check in-game and flip `yaw` by π in the manifest if needed;
  your code must just honour `yaw`.
- Some models lack normals (the simplifier dropped them) — call
  `computeVertexNormals()` when absent. Some have no textures (Century is
  flat grey) — the paint rule (§4.11) applies to the largest-area material.
- GLTFLoader: `import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js'`
  (allowed in punk/). Textures are WebP (EXT_texture_webp is supported by
  GLTFLoader). Load lazily when the layer first attaches; while loading,
  keep drawing the fleet boxes (do not hide them until models are ready).
- Register the layer in `layers.ts` after `props` (`layers.ts` is PM-owned
  but this ticket may add exactly that one line + import).
- Pure `vehiclemath.ts` (no three/webgpu import): weighted stable model
  pick `pickModel(i, weights)`, LOD choice `lodFor(distance)`, normalisation
  maths (`normaliseTransform(bbox, yaw, length)` → { scale, offset }),
  light-anchor derivation from a bbox.
- Performance (the user is on a MacBook): instanced draws only; no
  per-car Object3D; no allocation per frame; update matrices only for cars
  whose LOD bucket is visible.
- **Never open or read any `.png` / `.jpg` / `.glb` as an image.**

### For the reviewer / PM
- **Fleet boxes are hidden via the fleet MATERIAL's `visible`, not `mesh.visible`.** `main.ts:1808` only calls `cars.update(dt)` while `cars.object.visible` is true, so hiding the mesh (which the `layer.ts` JSDoc allows) would freeze the traffic. The material visibility is restored on detach, when the fleet changes and when `traffic()` returns null. The e2e exact-restore census passes. You may want to amend the `traffic()` JSDoc to match.
- **Forward direction:** the manifest says the model front is at +z after `yaw`, but a fleet instance travels along its local −z (`rotation.y = −heading`, heading 0 = −z). So the code adds `FLEET_YAW = π` on top of the manifest `yaw`. Please check in game; if a car drives backwards, flipping its manifest `yaw` by π still works as intended.
- **Performance fix worth knowing about:** reading texture pixels through a default (GPU-backed) OffscreenCanvas cost about 117 s of main-thread time under SwiftShader. That stalled the page and made `smoke: R cycles every render style` time out. With `willReadFrequently: true` it takes 22 ms. The smoke test now runs in 2.3–2.4 min (2.6 min baseline with the layer unregistered). Loading is still about 36–65 s wall time in SwiftShader (22 MB, all LODs in parallel). The fleet keeps its boxes until everything is loaded.
- **Material budget:** most GLBs have 7–44 materials, so ≤ 3 draws per (model, LOD) needs collapsing. Non-body materials become vertex colours; this is exact for the palette textures most models use, and approximate (≤ 64² nearest sample) for real photo textures such as the Crown Vic interiors. Emissive textures in non-body materials are dropped; the instanced light quads replace them.
- **Century:** requires `KHR_materials_pbrSpecularGlossiness`, which three r185 no longer supports (the loader only warns). I added a small loader plugin that maps diffuse colour/map and glossiness, so the Century gets its real colours and the loader stays quiet.
- **Doc vs repo mismatch (not touched):** architecture.md §4.11 says `public/models/cars/<id>/lod0.glb`, but the files are `<id>.lod0.glb` and the code follows the manifest file names. The manifest has no `lights` entries, so the anchors come from the bbox (the manifest override is supported).
- **Not touched, out of scope:** `CAR_HALF_HEIGHT` is not exported from `traffic.ts`. The half height is read from the fleet geometry's bounding box instead.
- **Not touched, out of scope:** `three/addons/loaders/GLTFLoader.js` is not in `vite.config.ts` `optimizeDeps.include`. The dev-server e2e was clean, but adding it would guarantee a single pre-bundled three in dev.
- **Not verified:** the ≤ 1.2 M triangle budget for the whole fleet at bank was checked only by the numbers above (57 k). I could not view images, so there was no visual check. The paint sheen, light placement and forward direction need the PM's GPU visual review.
