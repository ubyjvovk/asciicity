## Goal
A dozen red double-deckers endlessly driving the primary/secondary roads —
pass-through (no collision), pure ambience.

## Context
- New module `src/world/traffic.ts` (pure logic separated from three objects):
  1. `export interface RoadGraph { nodes: Map<string, Vec2>; edges: { pts: Vec2[]; a: string; b: string }[]; adj: Map<string, number[]> }`
     `export function buildRoadGraph(roads: Road[], classes: RoadClass[]): RoadGraph`
     — keep roads whose `cls` is in `classes` and `pts.length >= 2`; node key =
     endpoints quantised to 2 m (`Math.round(v/2)*2`, key `"x,z"`); `adj` maps
     node key → edge indices touching it.
  2. `export class PathWalker { constructor(graph: RoadGraph, rand: () => number); readonly x/z/heading: number; advance(dtMetres: number): void }`
     — starts on a random edge; walks the polyline at constant speed; at an
     edge end picks a random *other* edge from that node's adjacency (or
     reverses when none); `heading` = current segment yaw (atan2(dx, −dz)).
  3. `export class BusFleet { constructor(roads: Road[], count = 12, seed = 9); readonly object: THREE.Object3D; update(dt: number): void; }`
     — `buildRoadGraph(roads, ['primary','secondary'])`, `count` `PathWalker`s
     with `mulberry32(seed + i)`, speed 7 m/s. Geometry: one
     `THREE.InstancedMesh` of `BoxGeometry(2.5, 4.3, 10.2)` (double-decker
     proportions, length along z), `MeshLambertMaterial({ color: 0xc0392b })`,
     one instance per bus. `update` advances walkers and writes matrices via
     ONE reused `THREE.Object3D` dummy (`position.set(x, 2.15, z)`,
     `rotation.y = −heading`, `updateMatrix`, `setMatrixAt`,
     `instanceMatrix.needsUpdate = true`) — no per-frame allocation.
     Empty graph (no matching roads) → `count 0`, inert object.
- `main.ts`: create `BusFleet(city.roads)` (skip when `synthetic` — the grid
  city works too, so do NOT skip; just always create), `scene.add(fleet.object)`,
  call `fleet.update(dt)` each frame before `ascii.render`.
- Docs: `docs/world.md` Traffic section, `docs/integration.md` frame-loop note.

### Notes for the reviewer
- **"4 adjacent edge-ends" needs four arms, not two.** The ticket says “two 2-point primary roads sharing a centre point → …4 adjacent edge-ends”. With endpoint-only adjacency (per the `buildRoadGraph` spec: “node key = endpoints quantised”) two 2-point roads sharing one endpoint can only ever meet as a T/L (2 incident ends); a degree-4 node genuinely requires four 2-point arms meeting at the centre. The natural “+” of two crossing polylines (`[[-100,0],[100,0]]` + `[[0,-100],[0,100]]`) produces **zero** shared nodes because the crossing point is neither road's endpoint. I wrote the test with **four** 2-point primary arms sharing `(0,0)` so the assertion “1 shared node with 4 adjacent edge-ends (assert adjacency count)” holds exactly (`g.adj.get('0,0').length === 4`). Please reconcile the doc wording if a different cross was intended.
- three.js is **0.185**, where `InstancedBufferAttribute.needsUpdate` is a **setter-only** property (reading returns `undefined`). The `update` writes `instanceMatrix.needsUpdate = true` exactly per spec; the test asserts the `version` counter increments instead of reading `needsUpdate`.
- Buses start at a random point along a random edge (`rand()*len`) for good-looking spread; speed 7 m/s, both real and synthetic cities have primary/secondary roads so it is never skipped.
