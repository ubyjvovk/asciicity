## Goal
Central London tags roof shapes on 33 % of its building ways and colours on
~31–37 %; Kyiv on 10–17 %. We throw all of it away. Keep it: parse the OSM
Simple-3D-Buildings tags into the new optional `Building` fields
(`roof`, `osmColor`, `roofColor`, `material`) and validate them. The
rules are LOCKED in docs/data-format.md "Simple 3D Buildings: roofs,
colours, materials (wave 21)" (items 1–8) — read it first; the types are
already in `src/data/types.ts` (`BuildingRoof`, `RoofShape`,
`BuildingMaterial`).

## Context

  `heightOf(tags)` (≈ line 100) and `minHeightOf`; parts:
  `applyBuildingParts` (≈ line 812) — parts keep their own tags, outlines
  replaced by parts transfer only their name (unchanged behaviour). Add pure

  `parseColour(value)` (148 CSS names + `#rgb` / `#rrggbb` / 6 bare hex),
  `materialOf(tags)`, `compassToDeg(value)`. `ring` is the projected
  local-metre footprint (for R = √(area/π) and the longest-edge bearing).
  Bearing convention: degrees clockwise from north, where north is −z (see
  AGENTS.md "Coordinate system": x east, z SOUTH).
- Emit fields only when present (keep JSON small); round `roof.h` to 0.1,
  `dir` to 1°. Colours as 24-bit integers.
- Validator: `src/data/validate.ts` `validateCity` / tile validation — the
  item-7 rules; a bad optional field is an ERROR (same style as `minH`).
- The regeneration of datasets is T-0160 — do NOT run fetch-osm or touch
  `public/data/`.

**For the reviewer**
- `roof:orientation=across`: the spec says "longest-edge bearing + 90", and the AC expects an east-west 30×10 block → 0. A line's bearing is ambiguous by 180°, so I report the result in `[0, 180)`: EW → 0, NS → 90. An explicit `roof:direction` keeps the full `[0, 360)` range, since skillion roofs have a real direction.
- `roof.h` is rounded to 0.1 first, then clamped. The upper bound is exactly `h − minH − 1`, the same expression the validator uses, so a clamped value may not be a multiple of 0.1 (e.g. when `h` came from `ft`).
- `colour` is used only when `building:colour` is absent or empty. An unparseable `building:colour` does not fall back to `colour`.
- `compassToDeg` also accepts plain numeric strings, so `roof:direction` has one parser. Bare 3-hex values (`fff`) are rejected, per item 4, because the `#` is optional only for 6 hex digits.
- For T-0160: after conversion, later steps (landmark fixes, presets) could lower a building's `h` below `roof.h + minH + 1`, which would then fail validation. I did not audit those scripts because they are out of scope.
