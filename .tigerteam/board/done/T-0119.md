## Goal

T-0118's longest-chain rule assumed each bridge road name chains into one
polyline — but Sydney's `Bradfield Highway` is a DUAL carriageway: two
near-identical chains (1630.6 m and 1634.6 m). Only the longest gets the
49 m apex, so the west carriageway lerps at ~28 m ASL — a 21 m cliff
between the two halves of the same deck (PM GPU probe on main:
`?city=sydney&at=151.21050,-33.85230` → ALT 28; twenty metres east reads
49). Rule change: the apex applies to EVERY chain whose arc length is
≥ 0.8 × the longest matching chain's length.

## Context

- The rule lives in `chainHumpApex` (`src/world/terrain.ts`, T-0118).
  Change "is the longest" to "length ≥ 0.8 × the longest matching
  chain's length". Ratio check keeps the T-0118 behaviour everywhere it
  was right: Cahill Walk's Circular Quay chain (661 / 1503 = 0.44)
  stays un-humped; single-chain names are 1.0; the Bradfield twins
  (0.998) both hump.
- `roads.ts` already calls the shared helper — no second edit site.
