## Goal
Make the matrix render style read like the film: MIRRORED half-width
katakana + digits raining, instead of the shared ASCII ramp it borrows
today. The glyphs ship as embedded bitmaps so the look is identical on
every machine (no installed-font dependency, no tofu on font-less CI).

## Context
- **Read first**: architecture.md §4.20 "Matrix katakana atlas" — charset,
  bitmap source, mirroring, ordering are locked. Current implementation:
  `src/render/styles/matrix.ts` (it imports `buildGlyphAtlas`,
  `DEFAULT_RAMP` from `./ascii` — that import goes away).
- Charset: half-width katakana `U+FF66`–`U+FF9D` (56 glyphs) + digits
  `0`–`9` = 66 glyphs.
- Bitmaps: 8×16 per glyph, derived from GNU Unifont's `.hex` glyph rows
  (each glyph = 16 bytes = 32 hex chars). Vendor them as constants
  (e.g. `const GLYPHS: Record<number, string>` codepoint → 32-hex-char
  row string). Fetch `unifont.hex` from a GNU mirror DURING DEVELOPMENT
  to extract the 66 rows; the repo gets only the constants (a few KB) —
  no network at build/test/runtime, no new dependency.
- Atlas build: rasterise each bitmap to the atlas canvas
  (nearest-neighbour to the cell size — chunky pixels are wanted),
  HORIZONTALLY MIRRORED. Order glyphs by ink coverage ascending (count of
  set bits), computed from the bitmaps at build time, so `matrixGlyph`'s
  density mapping is untouched except for the glyph-count uniform.
- Pure/node-testable parts: hex-row → 8×16 boolean bitmap decoding, ink
  count, coverage ordering, mirroring. Keep `hash3` / `matrixGlyph` /
  `rainIntensity` / `matrixBrightness` signatures unchanged.
- `src/credits.ts`: add a GNU Unifont attribution line (dual-licensed
  SIL OFL 1.1 / GPL v2+ with font-embedding exception; bitmap source).
  If `tests/credits.test.ts` does not exist, cover the line where the
  credits content is already tested (say where).
- The existing e2e style loop screenshots `style-matrix.png` — it must
  keep passing (assertions are non-visual; the PM judges the look on the
  GPU at review).
