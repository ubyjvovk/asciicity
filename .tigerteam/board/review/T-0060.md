## Goal
Implement `docs/architecture.md` §4.12 exactly: the minimap becomes its own
top-left panel, the HUD stays top-right, a ⚙ button (bottom-right, every
platform, mobile included) opens the pause/settings menu with `HUD` /
`MINIMAP` / `CRT` / `STYLE` / `FLY` rows plus the existing `COPY LINK` /
`SWITCH CITY`; `H`/`M` keys toggle the panels; settings persist in
`localStorage` and are mirrored into the URL; a credits footer reads
`src/credits.ts`. (The `LANDMARKS ▸` row is T-0061 — leave a stub row
labelled `LANDMARKS ▸` that does nothing yet, so the layout is final.)

  `?minimap=0` still means "off" (now a toggle default rather than
  never-created: create the panel always, hide it when off).

  `setCrt(on)`) so the toggle can show/hide it without re-mounting.
- `Hud`: nothing structural; `docs/hud.md` layout section updated.
- Keys: `H` (HUD) and `M` (minimap), keydown without repeat, ignored while
  the picker is open. FLY row calls the same code path as `F` (feed a
  `flyToggles` increment or flip `state.fly`; either is fine as long as
  `stepPlayer` stays pure).
- e2e: extend `smoke: boots…` or add `smoke: panels`: `#mini` and `#hud`
  both visible at boot; press `M` → `#mini` hidden and
  `localStorage['asciicity.settings']` contains `"minimap":false`; press
  `H` → `#hud` hidden; click `#gear` → overlay visible with the `HUD: OFF`
  and `MINIMAP: OFF` rows; click `MINIMAP: OFF` → `#mini` visible again;
  `#credits` contains `@ubyjvovk` and links to the repo URL.
- Docs: `docs/integration.md` (panels, gear menu, keys, persistence, URL
  mirroring, credits), `docs/hud.md`.

**What failed:** the ⚙ button is not the hit target at its own location — Playwright's `page.locator('#gear').click()` (no `force`) times out with `<canvas id="view"> intercepts pointer events`. Your capture-phase workaround on `#view` (swallowing pointer events whose coordinates fall inside the gear box) makes a tap *work* but the button itself never receives events: no `:hover`/`:active`, wrong after a resize until the box is re-measured, and no automation can drive it. The cause is stacking order, not WebGL: the canvas is painted above the fixed-position button.

**Done looks like:**
1. Put the chrome above the canvas with explicit stacking: `#view { z-index: 0 }`, `#mini`, `#hud`, `#gear`, `#credits`, `#toast` `z-index: 5`, `#overlay` above those (keep whatever it has, ≥ 10), the CRT overlay below the chrome and `pointer-events: none` (it already is `none` — confirm). Remove the coordinate-box capture handler on `#view` entirely; `#gear` handles its own `click`/`pointerdown` (with `stopPropagation`, as before).
2. Evidence to include: `page.locator('#gear').click()` **without** `force` succeeds on desktop after pointer lock was acquired by a canvas click (call `document.exitPointerLock()` first if lock blocks the synthetic click — say which), and on the 390×844 touch emulation `page.locator('#gear').tap()` succeeds and `__asciicity.state` stays unchanged; re-quote the four bounding boxes on both viewports.
