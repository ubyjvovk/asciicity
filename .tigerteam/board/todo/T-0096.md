## Goal
One real-city boot path: retile the three remaining monolithic cities with
the T-0093 tiler, update the registry, delete the monolithic JSONs. After
this ticket every `?city=` boots tiled; the monolithic in-memory path
remains ONLY for `?synthetic=1` and unit tests.

## Context
- **Read first**: architecture.md §4.19 (registry rules), data-format.md
  "Tiled datasets". T-0095 landed the tiled boot path with SF as the
  template — copy its registry-entry shape exactly.
- Migration commands (deterministic, no Overpass):
  `node scripts/tile-city.mjs public/data/city.json public/data/london`
  `node scripts/tile-city.mjs public/data/kyiv.json public/data/kyiv`
  `node scripts/tile-city.mjs public/data/nyc.json  public/data/nyc`
  then DELETE `public/data/city.json`, `public/data/kyiv.json`,
  `public/data/nyc.json`. (Registry ids stay `london`/`kyiv`/`nyc`.)
- Registry: each entry gets `tiled: true`, `file: 'data/<id>/index.json'`,
  `sizeBytes` = `stat -c %s` of that index.json. Blurbs/labels/default
  spawns unchanged.
- If `main.ts`/`load.ts` still carry monolithic-city branches that are now
  unreachable for registry cities, remove ONLY what is dead for registry
  cities — the synthetic path and `loadCity`+`validateCity` used by tests
  stay.
- Manhattan is the stress case: 41 k buildings, 586 bridge roads → all
  bridge roads must land in `index.bridgeRoads` (whole), and the Brooklyn
  Bridge presets must still spawn ON the deck.
