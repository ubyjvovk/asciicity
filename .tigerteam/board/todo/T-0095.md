## Goal
Wire sector streaming into the app: a registry entry with `tiled: true`
boots from `data/<city>/index.json`, streams tiles via `TileManager`
(T-0094), and San Francisco becomes the first migrated city — generated
with the T-0093 tiler, monolithic `sf.json` deleted. Every existing SF
behaviour (presets, GGB deck spawn, ships, coastline collision, loading
bar) must survive the migration.

## Context
- **Read first**: architecture.md §4.19 — the complete integration spec
  (boot order, event application, HUD/bus rebuild rules, debug surface,
  registry shape). §4.18 (loading), §5 (boot), data-format.md "Tiled
  datasets". `TileManager` and `CollisionGrid.addSource/removeSource` are
  landed (T-0094); the tiler CLI is landed (T-0093).
- Boot (tiled): index via `loadCityJson` (phase `download`, sizeHint =
  registry `sizeBytes`) → `validateTileIndex` → globals (terrain, water +
  levels, rivers/boats, ship lanes, `bridgeRoads` → chaining + BridgeDecks
  + groundAt + a permanent rendered pseudo-tile with collision source
  `'bridges'`) with `await nextFrame()` between builders → spawn tile 3×3
  (phase `build`, step `TILE <i>_<j>`, bar = completed/Σ bytes of that
  3×3) → `ready`. Rest of 5×5 streams after ready.
- Frame loop: `tiles.update(x, z)` then apply `tiles.take()` — `add` →
  build the tile's Group (existing builders: buildings, roads, trees; same
  `groundAt`) + `collision.addSource(key, …)`; `remove` → detach, dispose
  geometries/materials, `removeSource`. ≤ 1 add per frame comes free from
  `take()`.
- Rebuilds on `snapshot().version` change, throttled to ≤ 1/s, scheduled
  outside the render path: ZoneIndex, tag anchors, `minimap.setCity(...)`
  (add this method — ctor unchanged), and the bus fleet from
  `snapshot().roads` + `index.bridgeRoads`, seed `9 ^ version` (buses
  teleport on rebuild — accepted, do not smooth).
- Spawn: adapt `landmarkSpawn` to accept `{name, x, z}` anchors
  (`index.landmarks`, first entry per name wins); `parseAt`/`resolveSpawn`
  use `index.bbox`. Presets must resolve BEFORE any tile fetch so the 3×3
  centres on the spawn.
- Debug: `window.__asciicity.tiles = { loaded, pending, version, disposed }`
  (live); `?tileradius=<m>` scales loadR/unloadR proportionally
  (2000/2600 × m/2000).
- Registry: SF entry → `tiled: true`, `file: 'data/sf/index.json'`,
  `sizeBytes` = committed index.json size (`stat -c %s`). Migration:
  `node scripts/tile-city.mjs public/data/sf.json public/data/sf`, commit
  the directory, DELETE `public/data/sf.json`. London/Kyiv/NYC stay
  monolithic until T-0096 — both boot paths coexist in this ticket.
- `?synthetic=1` and the monolithic path must remain byte-identically
  behaved (all existing unit + e2e tests are the regression net).
- Existing e2e specs (GGB deck `y > 20`, alcatraz, ships, presets) must
  pass unchanged; if one genuinely depends on the monolithic sf.json path,
  adjust it minimally and justify each edit in your report.
