## Goal
CI (GitHub Actions `pages` run for 11d845d) failed on
`tests/landmarks.test.ts > sf fixes still target their names after the nyc
table lands` with `Test timed out in 5000ms` (it ran 9 886 ms on the shared
runner; the whole file took 11 s). Cause: since the wave-11 migration the
test helpers reconstruct a city by fs-reading `index.json` + all tile files
(SF = 69 files ≈ 15 MB) — and they do it AGAIN for every test that calls
them. Fix the waste and give data-driven tests slack; the deploy is blocked
on this.

## Context
- `tests/sfCity.ts` and `tests/tiledCity.ts` are the helpers (T-0095/96).
  Add module-level memoization: each city's parsed index / globals / full
  reconstruction is computed ONCE per process and returned by reference
  afterwards (tests only read). Vitest workers are per-file, so this
  collapses repeat loads within each test file.
- Belt and braces: in the dataset-heavy test FILES listed in scope, set a
  per-file `testTimeout` of 30 000 (e.g. vitest's
  `describe`/`it` timeout arg or a top-of-file
  `vi.setConfig({ testTimeout: 30_000 })` — pick the idiom already used in
  the repo if one exists) so a cold-cache first test on a slow runner still
  passes. Do NOT touch the global vitest config.
- CI log for reference: run `pages` on sha `11d845d`, job `build`, step
  `Run npm test`.
