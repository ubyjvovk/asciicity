## Goal
Replace the placeholder `main.ts` with the real bootstrap and frame loop so
the game is playable: load the city (or the synthetic fallback), build the
three world meshes, walk with collision, render through the ASCII pass, and
drive the HUD.

## Context
- Contract: `docs/architecture.md` §5 (bootstrap steps 1–5, exactly), §3
  (camera orientation from yaw/pitch), §6, §7 (no per-frame allocation).
  Every module you need already exists — read their exports; do not modify
  them (flag problems in your report instead).
- Expose `window.__asciicity = { ready: boolean; state: PlayerState; fps: number; cols: number; rows: number }`
  (declare the global in `main.ts` with `declare global`). `ready` flips to
  `true` after the first rendered frame. The e2e test (T-0011) relies on it.
- `#overlay` shows the title and `CLICK TO ENTER`; the first click hides it
  and requests pointer lock via `Controls`. Pressing `Escape` (pointer lock
  lost) shows a smaller `CLICK TO RESUME` overlay.
- Spawn per §5 step 2 (yaw `−π/2`, walk +x until not `blocked`).
- URL params: `synthetic=1`, `cell=WxH` (e.g. `cell=8x16`), `seed=N` for the
  synthetic city.
- Style: canvas fills the viewport; `#hud` fixed top-right 320 px wide, black
  background with a 1 px `#1f5a2a` border; overlay centred, green on black.
- Verify visually yourself: the worker image has Playwright's chromium at
  `/opt/pw-browsers` and `@playwright/test` is installed — you may run a
  throwaway script (do not commit it) that opens `http://127.0.0.1:5173/?synthetic=1`
  from `npx vite --port 5173`, clicks, and screenshots; use launch args
  `--enable-unsafe-swiftshader --ignore-gpu-blocklist --use-angle=swiftshader --disable-dev-shm-usage --no-sandbox`.
  Describe what you saw in the report.
- Write `docs/integration.md`: startup sequence, URL params, the
  `window.__asciicity` contract, and how to add a new world layer.
