## Goal

Apply the wave-13 bare-earth DEM filter to Kyiv the way T-0108 applied it
to Tokyo: regenerate `terrain` + `waterLevels` IN PLACE from the cached
`N50E030` tile with `--dem-bare` semantics — streets flatten where roofs
contaminated them, while Kyiv's REAL relief (the Dnipro bluffs, 120 m of
it) must survive the filter.

## Context

- **Follow T-0108's recipe exactly** (`.tigerteam/board/done/T-0108.md`,
  the Answers section + report): regenerate the absolute grid from the
  cached DEM tile with the 9×9 erode + double 3×3 smooth
  (`scripts/dem.mjs` `buildTerrain` with `bareEarth: true`), same grid
  dims/origin/step; hard guard that the changed key set of `index.json`
  is exactly `{terrain, waterLevels}` (deep-compare; datum may change
  only via terrain); tiles byte-untouched; atomic write; no Overpass.
  The DEM cache is `.cache/dem/N50E030.hgt.gz` (re-download from the
  skadi mirror if absent — that is allowed).
- `npm run fetch-data:kyiv` now carries `--dem-bare 1` (already
  committed), so a future full refetch reproduces the same terrain.
- **The risk is the opposite of Tokyo's**: the erode window is ~250 m
  wide, and Kyiv's bluff crests (Lavra, Volodymyr Hill, the funicular
  top) are real terrain that a min-type filter can shave. The bounds
  below protect them; if one fails, STOP and file a blocked question
  with the full pre/post table — never tune a bound or the filter
  (wave-13a lesson: bounds respect real relief; a mechanism change is
  the PM's call).
- Registry rule: `sizeBytes` for kyiv in `src/data/cities.ts` = the new
  `index.json` byte size.
