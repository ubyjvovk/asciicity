## Goal
Build the data-side half of sector streaming (wave 11): a pure tiler that
turns a monolithic `CityData` into `index.json` + `tiles/<i>_<j>.json`, a
`--tiles` mode and a `--chunks NxM` chunked-fetch mode in `fetch-osm.mjs`,
the height clamp raised to 650, and `validateTileIndex` in `validate.ts`.
No runtime code — the app does not load tiled data yet (that is T-0094/95).

## Context
- **Read first**: docs/data-format.md section "Tiled datasets (wave 11 —
  sector streaming)" — it is the complete spec for this ticket (tile grid,
  the 7 tiler rules, `--chunks`, clamp). Types: `TileIndexData`, `TileData`,
  `TileStat`, `LandmarkEntry` in `src/data/types.ts` (PM-owned — import,
  never edit).
- `scripts/tile-city.mjs` is NEW: a pure `tileCity(city, tileSize)` →
  `{ index, tiles: Map<key, TileData> }` plus a thin CLI
  `node scripts/tile-city.mjs <city.json> <outdir>` that validates input
  with `validateCity` (import from `src/data/validate.ts` the way
  `osm-convert.mjs` structures its imports — it is an .mjs/zero-dep script;
  if importing the TS validator from an .mjs script is not workable, put an
  equivalent structural check in tile-city.mjs and say so in your report).
- `fetch-osm.mjs --tiles`: after conversion, run `tileCity` and write the
  directory named by `--out` instead of one JSON. `--chunks NxM`: split the
  bbox into N×M sub-bboxes, fetch sequentially (5 s pause, existing
  endpoint-fallback logic), concatenate `elements`, dedupe by `type`+`id`
  BEFORE conversion. Keep both flags orthogonal to every existing flag.
- Clamp: `[3, 600]` → `[3, 650]` in `osm-convert.mjs` (the `clampHeight`
  path around line 128) and in `src/data/validate.ts`. `types.ts` and the
  docs already say 650. No shipped dataset has h > 600, so committed JSONs
  stay byte-identical — do NOT re-fetch or touch `public/data/`.
- The wave-9 ordering lesson applies to road splitting: the boundary
  crossing point is computed ONCE and appended to BOTH pieces, and the
  result must be independent of vertex order / travel direction.

## Acceptance criteria
- [ ] `bash .tigerteam/scripts/run-tests.sh tests/tile-city.test.ts tests/validate.test.ts` exits 0, and the full
      `bash .tigerteam/scripts/run-tests.sh` stays green.
- [ ] `tests/tile-city.test.ts` covers, by name: (1) union round-trip — tiling
      the synthetic city (`syntheticCity()`) and concatenating all tiles
      reproduces every building/tree/woods element exactly once, input order
      preserved within a tile; (2) building assignment by unrounded vertex-mean
      centroid, deterministic; (3) a road crossing a boundary is split with
      exactly coincident endpoints in both pieces, and splitting the reversed
      polyline yields the same crossing point; (4) a segment that cuts a tile
      corner (no vertex inside) still produces a piece in that tile; (5) a
      U-shaped road re-entering a tile yields two pieces with the same `id` in
      that tile; (6) roads with `bridge: true` land whole in
      `index.bridgeRoads` and appear in NO tile; (7) `landmarks` is in tile
      scan order (j asc, i asc, input order) with one entry per named
      building; (8) empty tiles are absent from `tiles` and no file is
      written; (9) `tiles[key].bytes` equals the written file's byte length;
      (10) single-point degenerate road pieces are dropped; (11) negative
      tile indices key as `"-3_2"` style.
- [ ] CLI determinism: running `node scripts/tile-city.mjs` twice on the same
      input produces byte-identical files (test via temp dirs, or a
      determinism unit test over serialized output).
- [ ] Chunk logic is tested as pure functions with NO network: bbox N×M split
      covers the bbox exactly with no overlap gaps, and dedupe by `type`+`id`
      keeps one copy of a seam element.
- [ ] `tests/validate.test.ts` gains: `validateTileIndex` accepts a good
      index; rejects a bad tile key, non-positive `tileSize`, missing
      `bridgeRoads`; `validateCity` accepts h = 650 and rejects h = 651.
- [ ] `docs/fetch-osm.md` documents `--tiles`, `--chunks NxM`, and the
      standalone `tile-city.mjs` migration command.
- [ ] Every new exported function has a one-line JSDoc.
- [ ] No files changed outside scope.
