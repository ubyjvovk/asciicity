## Goal
User report: after the pointer lock is lost by an OS action (macOS
screenshot shortcut), the game cannot regain it short of a reload — keys
work, Escape does nothing, no overlay. Root cause in the code: a rejected
`requestPointerLock()` is swallowed at every call site, there is no
`pointerlockerror` listener, and Escape has no handler outside the
browser's own lock-exit event. Make lock failures visible, Escape always
functional, and the game playable without a lock. Contract:
`docs/architecture.md` §4.7 "Wave 10 amendment (T-0091)" — read it first;
it is the spec.

## Context
- `src/player/controls.ts`: drag-to-look when unlocked (`mousedown` →
  `mousemove` clientX/Y deltas → `lookDx/lookDy`, same sensitivity as the
  locked path, `isMouseSpike` filter; end on `mouseup`/`mouseleave`);
  `onClick` awaits `requestPointerLock()` (`Promise.resolve(...)` so
  browsers returning `undefined` still work) and calls a constructor-
  provided `onLockError(reason: string)` on rejection; also listen for
  `pointerlockerror` and route it there. `dispose()` removes everything.
- `src/main.ts`: implement the lock-failure state from the contract
  (overlay prompt `POINTER LOCK UNAVAILABLE · DRAG TO LOOK`, one retry,
  then drag-look mode), the Escape handler when unlocked (toggle
  `openSettings()` / resume; keep the existing LANDMARKS-submenu Escape
  behaviour first), `window.__asciicity.pointer` live object, and route
  main.ts's own two `requestPointerLock()` calls through the same error
  path. Keep everything else in main.ts untouched.
- `src/hud/hud.ts`: the help line shows `DRAG LOOK` instead of `MOUSE
  LOOK` while `pointer.dragLook` is true (find how the help line is
  composed; keep the touch variant as is).
- `tests/controls.test.ts` (existing file; add cases): `'drag-to-look feeds lookDx/lookDy from clientX/Y deltas while unlocked'`,
  `'drag-to-look ignores mousemove without a button down'`,
  `'a rejected requestPointerLock reports through onLockError'` (stub
  `target.requestPointerLock` to return a rejected promise).
- NEW `e2e/pointer.spec.ts` (headless Chromium has no pointer lock, so the
  failure path is what runs): boot `/?synthetic=1`, click `#overlay` →
  expect the overlay to re-appear with `DRAG TO LOOK` in `#overlay p` and
  `__asciicity.pointer.failures >= 1`; click again → overlay hidden,
  `pointer.dragLook === true`; `page.mouse` drag 200 px across `#view` →
  `state.yaw` changes by a non-zero amount; press `Escape` → `#overlay`
  visible with the pause menu; press `Escape` again → hidden. Never edit
  `smoke.spec.ts`.
- `docs/integration.md`: "Pointer lock and drag-to-look" note (states,
  `__asciicity.pointer`, the Escape rule).
