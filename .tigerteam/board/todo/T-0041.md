## Goal
The validator accepts (and correctly rejects) the two new optional fields
`terrain` and `waterLevels` (`docs/data-format.md` §Schema rules), and
`syntheticCity` can emit a deterministic hill so terrain can be unit- and
e2e-tested without real data.

## Context
- `src/data/types.ts` already carries `TerrainData`, `CityData.terrain?`,
  `CityData.waterLevels?` (PM-owned — do not edit).
- Validator: follow the existing style in `src/data/validate.ts` (first
  problem throws an `Error` whose message names the path). Paths to use:
  `terrain.x0`, `terrain.z0`, `terrain.step`, `terrain.cols`, `terrain.rows`,
  `terrain.datum`, `terrain.heights` (not an array / wrong length),
  `terrain.heights[i]` (non-finite), `waterLevels` (not an array, or length ≠
  `water.length` — including present with no `water`), `waterLevels[i]`.
  `cols`/`rows` must be integers ≥ 2, `step > 0`. Validate after `rivers`.
- Synthetic: `syntheticCity(seed = 1, blocks = 12, hills = false)`. With
  `hills` add `terrain` per `docs/data-format.md` §Synthetic city: step 20,
  grid covering the block extent (`blocks · 74 / 2` each way from the
  origin) plus one cell of margin on each side using the same
  `x0/z0/cols/rows` formula as §Terrain, `datum = 0`,
  `h(x, z) = 30·exp(−((x − 200)² + (z + 150)²) / (2·220²)) + z / 200`, rounded
  to 0.1 (`Math.round(v·10)/10`). No `waterLevels` (the synthetic city has no
  water). `hills = false` must produce byte-identical output to today
  (existing determinism tests must keep passing untouched).
- `docs/testing.md`: a short paragraph on `?synthetic=1&hills=1` /
  `syntheticCity(seed, blocks, true)` as the terrain fixture.

## Acceptance criteria
- [ ] `bash .tigerteam/scripts/run-tests.sh tests/data.test.ts` exits 0
- [ ] New validator tests, by name: accepts a valid 2×2 `terrain`; rejects `heights` length ≠ cols·rows (`terrain.heights`), `step: 0` (`terrain.step`), `cols: 1` (`terrain.cols`), `cols: 2.5` (`terrain.cols`), `NaN` height (`terrain.heights[3]`), non-finite `datum` (`terrain.datum`); accepts `waterLevels` of the same length as `water`; rejects length mismatch (`waterLevels`), `waterLevels` present without `water` (`waterLevels`), non-finite entry (`waterLevels[0]`); a city with neither field still validates
- [ ] New synthetic tests, by name: `hills = false` has no `terrain` key; `hills = true` yields `step 20`, `heights.length === cols·rows`, grid bounds enclose ±(blocks·74/2) with ≥ one cell of margin, the node nearest the origin is within 0.1 of the formula, every height is a multiple of 0.1 (within 1e-9), two calls are deep-equal, and `validateCity(syntheticCity(1, 12, true))` passes
- [ ] `bash scripts/check.sh` exits 0; JSDoc on changed exports; `docs/testing.md` updated
- [ ] No files changed outside scope
