## Goal
Refetch the Tokyo tiled dataset with the wave-12 bbox v2
`139.692,35.645,139.820,35.715` (the v1 box plus the west strip holding
Shibuya and Shinjuku). Origin stays Tokyo Station, so the tile grid and
every existing local coordinate are unchanged — new tiles simply appear
to the west.

## Context
- **Read first**: data-format.md "Central Tokyo … bbox v2 wave 12" — the
  bbox, chunking, counts and stability guarantees are all there.
- Command: `npm run fetch-data:tokyo` (already updated to bbox v2 +
  `--chunks 4x3`). Delete the old `public/data/tokyo/` first
  (`rm -rf public/data/tokyo` then fetch) so stale tiles cannot linger.
- West-strip counts at boarding: 57 539 buildings / 17 230 highways —
  expect ≈ 170 k buildings and ≈ 25–35 MB total. Budget stays **60 MB**
  (blocked question if over).
- Overpass etiquette per T-0097: retry a failed chunk after 60 s; if both
  endpoints keep failing, `## Questions`, do not hammer.
- `src/data/spawn.ts` and `tests/spawn.test.ts` are in scope ONLY for
  this: a refetch can shift a road vertex an existing preset sits on. If
  a wave-11 preset assertion fails on the new data, adjust that preset's
  `lon`/`lat`/`bearingDeg` minimally (nearest passing road vertex, same
  tile and view intent, per the T-0098 derivation rules) and justify each
  adjustment line-by-line in your report. Do NOT add new presets.
- `src/data/cities.ts` is in scope ONLY for the tokyo `sizeBytes` value
  (exact `stat -c %s` of the new index.json).
