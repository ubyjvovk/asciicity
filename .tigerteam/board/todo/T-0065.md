## Goal
Kyiv "looks very weird with no trees". Implement `docs/data-format.md`
§Trees exactly: fetch tree nodes, tree rows and wood/forest/park polygons;
emit `trees` (`[x, z, h, r]`) and `woods` rings; validate them; regenerate
**both** datasets (`npm run fetch-data:kyiv` and `npm run fetch-data`).

## Context
- Converter rules, densities, exclusion buckets, PRNG and the 40 000 cap are
  all in data-format.md §Trees — implement them literally; `mulberry32` is
  the same function as `src/data/synthetic.ts` (copy it into the script).
- Validator: `src/data/validate.ts` — optional `trees` (finite quads,
  `3 ≤ h ≤ 40`, `1 ≤ r ≤ 15`; paths `trees`, `trees[i]`) and `woods`
  (ring rules; `woods[i]`), after `rivers`.
- Fixture: add two `natural=tree` nodes (one with `height=12`), one
  `tree_row` way (~30 m), one `natural=wood` closed way (~60×60 m) containing
  one building and crossed by one road; tests: node trees emitted with
  their heights (12 vs seeded 6–14), the row yields 3–4 trees ≈ 8 m apart,
  the wood fill has ~24 ± 8 trees and none inside the building or within
  6 m of the road, output is byte-identical across two runs, the cap thins
  fills only (unit test with a tiny cap parameter exposed for tests).
- Datasets: both regenerated; report the summary lines and tree counts
  (expect Kyiv in the tens of thousands — Trukhaniv/Hydropark forests — and
  London a few thousand); files stay < 10 MB.
- Docs: `docs/fetch-osm.md` (selectors, summary line, trees section).
