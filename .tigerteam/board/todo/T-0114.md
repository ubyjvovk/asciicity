## Goal

Give the Sydney Opera House its sails: a synthesised spec-table structure
(`src/world/opera.ts`) of nested white spherical-patch shells on the OSM
podium — extruded prisms cannot read as the building, and it is the one
Sydney landmark everyone will look for first.

## Context

- **The contract is `docs/architecture.md` §4.22** — `OperaShellGroup` /
  `OperaHouseSpec` / `OPERA_HOUSES`, the sail geometry rule (mirrored
  same-radius sphere patches meeting at a rising ridge arc, dark mouth
  wall), the sydney table values, wiring, budget. Read it first.
- Pattern: `src/world/bridge.ts` (spec table → pure MeshData builder →
  `make*Object` wired once in `main.ts` beside `makeBridgesObject` — the
  shells are permanent, not tiled).
- The real podium outline is in the dataset since T-0116 (building
  `Sydney Opera House`; T-0110/0116 reports carry its massing).
  Reconcile §4.22's group bases/axes against that footprint so every sail
  stands on the podium; report the deltas from the table's hypothesis
  coordinates.
- T-0111 set the landmark fix (ivory podium, no fake height). If the
  refetched data carries `building:part`s that fake the roof over the
  podium, suppress them via the sydney `LANDMARK_FIXES` entry (§4.22
  rule) — the outline stays.
- The module adds NO tag anchor (the OSM building already supplies the
  floating tag).

## Acceptance criteria

- [ ] `OPERA_HOUSES` has exactly one entry (`sydney`) per §4.22;
      `buildOperaHouse` is pure and exported; `makeOperaObject` returns
      an empty object for every other city id.
- [ ] `tests/opera.test.ts` (committed sydney tiles via the memoized
      helpers): tallest ridge tip y = (67 − datum) ± 1; every sail-base
      vertex lies inside the `Sydney Opera House` footprint expanded by
      6 m; per group, tip x/z of each sail lies bearing-ward of its base
      (the sails lean toward the harbour); every vertex y ≥ podiumASL −
      datum − 0.5; vertex count < 20 000; no NaN; non-sydney →
      empty MeshData.
- [ ] `main.ts`: one `scene.add(makeOperaObject(...))` beside the
      bridges call; nothing else there.
- [ ] `docs/architecture.md` §4.22 amended with as-built notes
      (reconciled bases/axes, part-suppression outcome, vertex count).
- [ ] `bash .tigerteam/scripts/run-tests.sh` exits 0 (full suite).
- [ ] No files changed outside scope.

## Out of scope

Interior/collision (visual-only like the bridges), dataset changes,
presets/e2e (the `operahouse` preset exists from T-0111; the PM verifies
the look on the GPU — the sail SHAPE is judged there, not by unit test),
any other landmark. If the podium footprint from the data cannot host the
§4.22 table (axes off, groups overflow), file a blocked question with the
footprint's local-coordinate outline instead of silently shrinking sails.
