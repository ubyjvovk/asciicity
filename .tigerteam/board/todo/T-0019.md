## Goal
When pointer lock is acquired, Chromium delivers a first `mousemove` whose
`movementX/Y` equals the jump from the last pointer position (observed:
640/360 px in headless tests) — the camera spins on every first click.
Ignore the first `mousemove` after lock acquisition and any single-event
delta beyond a spike limit.

## Context
- `src/player/controls.ts` (T-0008/T-0013). Keep the public API unchanged.
- Add an exported pure helper `isMouseSpike(dx: number, dy: number, limit = 300): boolean`
  (true when `|dx| > limit || |dy| > limit`).
- `Controls`: listen for `document` `pointerlockchange`; when
  `document.pointerLockElement === target` set a private `skipNextMove = true`.
  In `onMouseMove` (while locked): if `skipNextMove`, clear it and return
  without accumulating; else if `isMouseSpike(e.movementX, e.movementY)`
  return without accumulating; else accumulate. Remove the listener in
  `dispose()`.
- Document the behaviour in `docs/controls.md` ("Pointer-lock entry" paragraph).
